# Related walk, supersede demotion and --neighbors (PLAN 5.3)

> `Relater.Related` walks resolved edges both ways in a recursive CTE (depth 1..3, each edge once, read from its nearer end); `Retriever.Superseded` feeds a post-fusion RRF penalty; `--neighbors` is a pure render step over depth-1 rows.

**Fact.**
- `store.Relater.Related(path, depth)` (sqlite/related.go): CTE `walk` over resolved edges, one recursive arm per direction (UNION plus the depth bound make cycles safe), `near` = min distance per node, `cand` = rowids of edges with an end in `near` closer than the depth, then those edges. Every step is an index lookup (src via the primary key, dst via `edges_dst`); never join edges with `src = x OR dst = x` or scan all edges per call: that version cost 7.7 ms per call at 5k entries / 25k edges, the index form 0.74 ms (`BenchmarkRelated`). The `AND dst IS NOT NULL` in the walk and the final `min(ds, dd) < depth` filter are redundant guards (hand SQL mutants survive them as equivalent). A `RelatedRow` has Via (nearer end), Path (far end, "" when dangling), Target (link as written), Direction (`out` when src is the nearer or an equal-distance end), Depth. `store.RelatedModel` is the same walk in Go; the contract test and `FuzzRelated` compare them. Depth outside 1..3 is Usage, an unknown path NotFound.
- Supersede: `Retriever.Superseded(paths)` = targets of a `supersedes` edge from a different, existing entry (a deleted superseder cascade-deletes its edges, a self-supersede is ignored). `Searcher.demoteSuperseded` runs after `ChunkMeta` and before the diversity cap: RRFScore *= `search.supersede_penalty` (default 0.5, 0..1, already in the config hash), flags `Candidate.Superseded`, re-sorts with `fusedBefore`. Penalty 1 reads nothing. Hit JSON gets `superseded` (omitted when false); explain gets `superseded` and `supersede_penalty` per candidate plus the setting. Mutual supersession demotes both.
- `--neighbors` (cli/search.go `neighborLines`, render/neighbors.go): depth-1 `Related` for each primary-store hit; a neighbour that is a hit, dangling or the entry itself is dropped; each neighbour is listed once, under the best-ranked hit; at most 5 per hit. Printed after the hits, before the `search_id=` footer, outside the render budget; `--json` adds `neighbors` (flat, `[]` when empty). It runs after the search is logged and writes nothing to the log. `kb context` has no `--neighbors`.

**Why it matters.** A new rel or edge reader must follow the same "resolved edges only" rule; the demotion order interacts with Merge (cross-store merge ranks on the already-demoted order).

**How to apply.** Change the walk in the CTE and `RelatedModel` together. A new Retriever/Index fake needs `Superseded` (search's `faultyRetriever` shows the pattern).
