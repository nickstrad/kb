# Feedback prior wiring and query memory (PLAN 6.2, 6.3)

> The prior is gated in `search.loadEvidence` and applied by `evidence.apply` (enabled, not --no-prior, judged searches as of asOf >= min_judged), multiplies the score after the supersede penalty and before the cap, and is logged as `search_results.prior` / `search_candidates.prior` (NULL = inactive). The query-memory list (6.3) reads the same evidence.

**Fact.**
- Gate: `[prior] enabled` and `Request.NoPrior == false` and `prior.Build(...).Judged() >= min_judged`. A closed gate changes nothing, logs NULL and never reads the log unless enabled and not `--no-prior`. `Outcome.Prior` (`PriorState`) carries the result; `PriorState.Inactive()` is the explain text (`prior inactive: 12/50 judged searches`, `--no-prior`, or no judged log). `prior.enabled = false` says nothing.
- Evidence: `Searcher.Prior` (a `store.JudgedLog`; the CLI sets it from the primary store, extra stores of a cross-store search have none, so they never apply it). Events: each `Verdict` (kind by `Useful`, rank = judged rank, `At` = `search_feedback.ts`), each `Opens` path (`OpenedAt[path]` = `search_opens.ts`, no rank). A whole-search `--none` names no (path, heading), so it is no evidence and not counted as a judged search. Verdicts on other stores' hits (`Store != ""`) and `OtherOpens` are ignored. An unparsable ts in the log fails `Judged` as a **Conflict** (exit 1, `sqlite.damagedLog`: "the search log in DB is damaged: the verdict on search N rank R has timestamp …; correct or delete that row"), never guesses. It is not Internal: a hand-edited log is a damaged database, not a kb bug; and since `kb eval`/`stats` read `Judged` too, Internal would turn every eval on such a log into exit 3 (W12 pass, harness `prior-hostile`).
- asOf: `Request.AsOf`, zero = `Searcher.Now` (the CLI sets `Now = d.clock` for explain as well). Build keeps events strictly before it. Eval replay (6.4) sets `AsOf` to the original search ts; because the evidence time is the feedback time, a verdict given after a search never reaches its replay.
- Order: supersede demotion, then prior, each re-sorting; both are multiplicative so the final score is fused x penalty x prior; then the diversity cap. The logged `rrf_score` already contains the prior; `prior` is the factor (every candidate gets one when active, 1.0 when it has no evidence, so NULL vs 1.0 tells inactive from neutral).
- Settings: `[prior]` is in `config.EffectiveJSON` (top-level `prior`), so every default settings hash changed at v8 and an eval baseline run with other prior params is not comparable. `search.Params.Prior` is a `prior.Params` (validated only when enabled).
- Evidence (6.4, Q133): `search.Evidence` (`NewEvidence(judged)`) is the log prepared once: `prior.NewIndex` sorts the events per key (O(E log E)) and `Index.Model(p, asOf, exclude)` answers the gate by binary search over each search's first event time and computes a key's u/n lazily from that key's events only, summed in Build's canonical order, so it equals `Build` over the kept events bit for bit (`TestIndexModelEqualsBuild`, search-level `TestEvidenceSliceEqualsFreshRead`). A `*Evidence` is a `store.JudgedLog`; `loadEvidence` uses a `Searcher.Prior` that is one as is (no read), else reads once and prepares it (the live path: ~4 ms instead of Build's ~8 ms at 10k searches, plus the ~32 ms read). The memory list gets only the searches with the query's MemoryKey (`Evidence.sameKey`, map built once).
- `Request.ExcludeEvidence` (6.4): search ids whose verdicts and opens the prior and memory leave out (count, u/n, memory). Eval sets it to the replayed query's own searches.
- A pinned clock (`KB_HARNESS_NOW`, harnessfake) makes feedback `at == asOf`, which Build drops: an E2E journey must advance `env KB_HARNESS_NOW=...` between the feedback and the search (J17).

**Query memory (6.3).**
- Gate: the prior's (`Outcome.Prior.Active`) plus `prior.query_memory` plus `search.list_weights.memory > 0` (a weight-0 list would only add zero-score candidates) plus a store that implements the optional `store.ChunkLocator`. `Outcome.Memory` (`MemoryState`) says why not (`memory inactive: 1/2 judged searches`, `--no-prior`, ...), from `PriorState.Reason()` (the prior's reason without its prefix; never trim the message). `--no-prior` therefore disables it.
- Key: `MemoryKey` = lowercase, sorted, unique words from the FTS sanitiser's own field split (`ftsWords`; a bare `and/or/not/near` or a field with no letter/digit vanishes, `draw-visual` is two words). Past searches (any mode, tag, k) with the same key count.
- List (decision in the pure `rememberedGold(judged, key, params, asOf)` and `memoryRowsOf(golds, ids, limit)`, L2 tables `TestRememberedGold`/`TestMemoryRowsOf`; `memoryRows` is the I/O shell around one `LocateChunks`): a second `prior.Model` built from only those searches' events (Enabled, MinJudged 0) gives u: gold = (path, heading) of useful verdicts, plus entries opened from those searches without a useful verdict (`Model.Opened`, first chunk of the entry, half weight). Sorted by u desc, path, heading; at most 100 looked up, `LocateChunks` (tag filter honoured) maps each to the first chunk by ord (the `ORDER BY c.ord` is also what the planner's `UNIQUE (entry_id, ord)` index returns, so a mutant dropping it survives; `TestLocateChunks` still pins the contract with chunks written last-ord first); a ref that no longer resolves is `Skipped`; the list is cut to `list_limit`. It enters `fuse` as a fourth list: `memory_weight/(rrf_k+rank)`, tie-break after the exact rank. A chunk only memory found has no fts/vec rank.
- Not logged: no `memory_rank` column (no schema change); it shows in explain and `--json` hits only.

**Why it matters.** 6.3's memory list shares the gate and `Searcher.Prior`; 6.4 replays with `AsOf`. The eval and stats readers see `prior` only through the log columns.

**How to apply.** Read `Outcome.Prior` for the gate, never recompute it. New search paths (context, eval replay) get the prior through `Searcher.Prior`; set it where a Searcher is built (`cli.newSearcher`).
