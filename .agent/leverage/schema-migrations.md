# Schema migrations
> Forward-only migrations of the store index DB carry the search log, the only irreplaceable data in a store; the lock, backup and apply sequence and the declared effects must be right.

- **Category:** data integrity
- **Status:** watch
- **Where:** `internal/migrate` (Steps, Run: flock on `migrate.lock`, backup `<file>.bak-v<N>-<ts>` via the artefact, apply, verify, prune to 3); adapters `internal/store/sqlite/artefact.go` + `migrations.go` (`index/0001..0007`, `Store.migrate` under BEGIN IMMEDIATE, `checkVersion`), `internal/embed/cache/artefact.go` (`cache/0001`), `internal/config/migrate.go` (config, location), `internal/cli/migrate_cmd.go` (`kb migrate`); planned v5–v8 (docs/PLAN.md §2.5).
- **Why it matters:** a bad migration silently corrupts or drops history. Since 1.8b (W7) only `kb migrate up` upgrades a durable file (backup under the flock first); every other open refuses an older one with "run kb migrate up", so the weakness is now: the lock, backup and apply sequence is correct, the refusal path is clear and writes nothing, and declared effects match reality.
- **Evidence:** v2/v3 log-preservation tests (`TestStepEffects`, `migrate3_test.go`). 1.2 (W3): `sqlite.Open` is the only version check; a failed migration rolls back (`TestOpenFaults`). 1.8a (W6): a cancel during the **last** step still committed (pinned `*sql.Conn` and mattn run statements on an already-cancelled ctx); fixed with a `ctx.Err()` check before COMMIT (`TestApplyCancelledMidStep`; knowledge sqlite-cancel-surfaces-as-interrupt). A negative `user_version` used to reach the migration loop; now Conflict "damaged".
- **Coverage today:** `internal/migrate` 98% statements, `TestRunDecisions` (24 rows: pending/fresh/current/newer × DryRun/NoBackup × lock free/held-released/held-past-wait/cancel-while-waiting × backup/apply/verify failures, Ctrl-C mid-apply), `TestRunConcurrent` (-race), `FuzzSteps`; mutate 88.8%, survivors equivalent (poll interval, perms, comparator magnitude). sqlite: fixtures `testdata/migrations/index-v1..v3.sql` (frozen SQL text) with `TestFixtures` (fixture == steps at its version, upgrade verifies, log rows kept), `TestReplay` (stepwise == fresh == Verify reference), `TestStepEffects`, `TestIndexSteps` (ID, Effect table), `TestApplyFaults`, `TestRunIndexConcurrent`, Verify drift/fk/integrity rows. cache: `TestCacheReplay`, `TestCacheArtefact`.
