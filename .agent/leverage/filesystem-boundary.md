# Filesystem boundary
> What kb reads, copies, edits and deletes on disk: entry discovery, symlinks, path arguments, and (from 1.5) in-place sources across a project.

- **Category:** external boundary · data integrity
- **Status:** watch
- **Where:** `internal/entry` (`Discover`, `Resolve`), `internal/cli/add.go` (copy and rollback), `rm.go` (directory deletes), `edit.go` (`$EDITOR`); `internal/config` `Read`/`ReadLocation` via `readCapped` (store `config.toml` and `.kb/kb.toml`: regular files only, 1 MiB cap enforced by stat and by a limited read) and `cli.loadConfig`; `internal/workspace` (`ResolveLocation`, `TargetLocation`, `Location.Store`, `ValidName`: location discovery, `--root`, `--global`, store names), `cli/init.go` (the only creator of `.kb/`); configured sources (`internal/entry/sources.go`, `internal/glob`, 1.5). `internal/links` (5.1) resolves paths purely, with no disk access: it is not part of this boundary until 5.2 matches link targets to entries.
- **Why it matters:** a mistake here deletes or exposes user files outside the store. In-place sources widen it from `data/` to whole repositories.
- **Evidence:** the harness found that symlinks under `data/` pointing outside the root are followed and indexed (DEFAULTS #65, carried to 1.5). `path-traversal` scenarios pass. W2 pass: front-matter titles/summaries with control bytes or 100 KB length were accepted (Q20, fixed: caps 200/1000 runes, no control characters, valid UTF-8); `reindex --all` on a root with no `data/` now reads it as an empty corpus and prunes every row (Q23) — correct for a derived index, but it is a whole-index delete triggered by a missing directory. W4 pass (1.1): discovery stats only `.kb/config.toml` / `.kb/kb.sqlite` (regular files, symlinks followed) walking up the physical parent chain; it never creates anything. `--root`/`--global` name a store that `add`/`reindex` then create (`.kb/` and `data/`) — so `kb --root ~ add x.md` makes `~` a legacy store that every directory under `~` then discovers (H28). The incident log follows the resolved store, else the user cache dir (TestIncidentLogPathDecision).
- **Coverage today:** harness `path-traversal`, `markdown-edges`, `front-matter-hostile`, `workspace-discovery` (W4: nested/symlinked cwd, not-found outside any store creates nothing, `--global` under HOME, relative `--root`, `--root`+`--global`); `workspace.TestResolve` (one row per branch outcome), `TestDiscoveryMetamorphic`, `FuzzDiscoveryUnderStore`; mutate on `internal/workspace` (only survivor equivalent, in the `assert.Post` condition); add rollback tests.
- **Next checks:** `exclude` patterns do not prune directories during the walk (`**/vendor/**` still walks vendor/: Q69); Resolve still walks every source (readdir and stat only now): if 10k-file stores matter, try the candidate paths directly and fall back to the walk for a dir entry's `Dir` form; harness H35 (refs × in-place sources) and H36 (case-fold overlap from the CLI); a `.kb` that is itself a symlink out of the tree (H29); a store named through a symlink by `--root` (kept unresolved by design, DEFAULTS candidate); 5.2: whether a body link resolving to a directory matches a directory entry.
- **W6 (1.7/1.4):** discovery now stats only `.kb/kb.toml` (regular file); `--root`/`--global` never create anything; only `kb init` creates a location or store (O_EXCL writes), and refuses `$HOME` and `/` without `--force` (H28 closed: harness `workspace-discovery` row, `TestInitDecisions`). A store name cannot leave `.kb/stores` (`ValidName`, `FuzzValidName`). Still open: a `.kb` or `.kb/stores/<name>` that is a symlink out of the tree (H29), `kb init --force` at `$HOME` makes the stray-ancestor trap again by choice.
- **W6 wave-end pass:** the 1 MiB cap (Q49) was a stat check before `os.ReadFile`, so `--root` on a location whose `kb.toml` is a symlink to `/dev/zero` (size 0, never ends) or a FIFO (open blocks) bypassed it: now refused as "not a regular file" before opening (`TestReadRefusesSpecialFiles`); discovery already required a regular `kb.toml`. Mutate: workspace 96.6% (MaxNameLen survivors fixed by deriving the name regexp from it; the rest equivalent). Harness `stores-layout` and `workspace-discovery` green.
- **W7 (1.5, in-place sources):** discovery now reads `[[sources]]` (entries dirs and `files` globs, root-relative) through `internal/glob` (own `**` matcher, `CouldMatchUnder` prunes the walk; `FuzzMatch`). A symlink that resolves outside the location root (a file, a dir entry's README or docs file, a glob base, an entries dir) is skipped with a warning and listed by `kb doctor` (DEFAULTS #65 closed: `TestDiscoverSymlinks`, harness `path-traversal` now fails on an indexed link, `in-place-sources`). Globs never walk `.git`, `.kb`, `node_modules`; symlinked dirs are not followed. `kb rm` refuses an in-place file; `kb add` writes only into the store's single entries dir. Two sources claiming one file is a Usage error before any write or prune. A missing source dir is still an empty source, so its rows are pruned (by design). Still open: a glob over a huge tree is walked on every `kb show`/`edit`/`rm` (Resolve discovers everything); case-insensitive collisions (`Docs/` vs `docs/` globs) are not detected.
- **W7 wave-end pass (measured):** `entry.Resolve` runs a full `Discover`, which walks every source and reads every file's front matter (`loadMeta`), on each `kb show`/`edit`/`rm`/`add`/`reindex <entry>`. Synthetic tree, 10,000 `.md` files in 200 dirs (+10,000 non-md files under `src/`), warm page cache: `Resolve` takes 0.50 s with `**/*.md` and 0.67 s with `docs/**/*.md` — linear in corpus size, paid before any work. Case-insensitive overlap confirmed on APFS: sources `docs/d000/*.md` and `Docs/d000/*.md` produce 100 entries for 50 files (paths `Docs/…` and `docs/…`), no overlap error, so every file is indexed twice. Earlier next checks closed by 1.5: symlinks under `data/` (DEFAULTS #65), `kb rm` on in-place sources (refused), missing source dir (empty source, rows pruned by design), `.git`/`node_modules` never walked; H28 closed in W6.
- **W7 wave-end fixes:** case-insensitive overlap is now detected: `discovery.add` keeps a lower-cased key per file and, when two spellings fold alike, `os.SameFile` decides; same file → the usual overlap Usage error naming both spellings (`TestDiscoverCaseFoldOverlap`; distinct files on a case-sensitive volume are unaffected). `Resolve` walks lazily (`discover(..., lazy=true)`: no front matter read) and loads only the entry it returns; `TestResolveMatchesDiscover` pins Resolve ≡ Discover per entry, `BenchmarkResolve` (2,000 in-place files): 59 ms → 4.3 ms. Overlap and symlink rules still run on the full walk. `kb index` refuses non-default stores so a files-only store can no longer overwrite the location's `index.md`.
