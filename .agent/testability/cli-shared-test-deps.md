# CLI tests share one mutable deps and the process cwd
> Every CLI test runs through one package-level `testDeps` and `os.Getwd`, so tests swap fields and `t.Chdir`, and none can run in parallel.

- **Smell:** global/process state · hidden coupling
- **Status:** needs work
- **Where:** `internal/cli/main_test.go:testDeps` (`= productionDeps()`), `internal/cli/add_test.go:useRoot` (`t.Chdir`), `internal/cli/root.go:deps` (mixes factories with per-run `caches *embedCaches`), `internal/cli/setup.go:withEmbedCache` / `downloadsModel` (take `*cobra.Command`, nil-tolerant for tests)
- **Symptoms in tests:**
  - 73 swaps of a `testDeps` field restored by `t.Cleanup` (openStore 15, modelCacheDir 14, embedder 14, editor 8, userCacheDir 7, embedCachePath 7, workspaceEnv 5, pullModel 3). `main_test.go` says "the CLI tests are not parallel": a forgotten restore leaks into every later test. (W7 count; was 62 at the first pass.)
  - 51 direct `t.Chdir` calls (21 in `init_test.go`) plus 58 `useRoot` calls, which chdir too. `workspace.Env` already has a `Cwd` field, but `testDeps.workspaceEnv` fills it from `os.Getwd`, so tests can only move the process. `t.Chdir` cannot be combined with `t.Parallel`.
  - Not one `t.Parallel` in `internal/cli` (0 hits, W7). `-race` never runs two commands at once in one process, so a race between two commands sharing `deps` cannot show up.
  - `deps.caches` collects the caches a run opened, and `finishEmbedCaches` drains it. That is per-run state on a struct every test shares.
  - `withEmbedCache` has `cmd != nil` branches and a `context.Background()` fallback below `main` (CODING_STYLE §4) only so tests can pass a nil command. `setup_test.go` and `embedcache_test.go` build `&cobra.Command{Use: name}` because the download policy is keyed on `cmd.Name()`.
- **Why it happens:** `deps` (CODING_STYLE §5) replaced package-level seams, but tests share one instance instead of building their own, and cwd discovery still reads the real process.
- **Remedy:** (1) `newTestDeps(t) *deps` returns a fresh value per test, with `t.TempDir()` for models and cache, and `run(t, d, args...)` takes it. (2) `useRoot` sets the `Cwd` that `d.workspaceEnv` returns instead of calling `t.Chdir`. (3) Move `caches` out of `deps` into a value `execute` owns. (4) Pass the download policy as a bool or option, not `cmd.Name()`. (5) Then add `t.Parallel` wherever there is no `t.Setenv`. Mechanical, but it touches every `internal/cli/*_test.go` → **new item** (Sonnet, test infra) in a wave where no other lane owns cli tests. Pair it with `cli-outcomes-only-as-text`.
- **Cost/benefit:** about a day of mechanical edits. It removes the cleanup-order coupling, lets `-race` see commands run at the same time, and lets new tests (3.2 cross-store, eval) be written parallel-safe from the start. The suite is fast already (cli 4.3 s), so speed is not the reason.
